## Account-system review and remaining blockers

| Area | Finding and required next step |
| --- | --- |
| Grant lifetime | Synthetic checks enforce exactly 14 x 24 hours; absent, foreign, revoked, pending, malformed and expired grants deny AI access. This is a per-business grant for an existing identity, not an account-provisioning workflow. |
| Workspace expiry | `requireBusinessMember` checks membership, not the grant. Record reads/writes and other authenticated routes remain accessible after expiry. Define and implement a consistent expired-account policy before invitations. |
| Isolation and permissions | Existing server-verified Auth and membership checks remain; customers cannot select their business using request IDs. Synthetic tests do not prove two independent live accounts, database RLS, MFA recovery or iPhone behaviour. Those acceptance checks remain outstanding. |
| Staff access | Sequential checks enforce the two-seat allowance, but invitation creation counts then inserts without an atomic seat reservation. The acceptance RPC checks invitation lifetime/recipient but not pilot lifetime or seat capacity. Concurrent invitations and accepting a pending invitation after pilot expiry need enforcement and retesting. |
| Billing | Scoped checkout and add-on mutations are blocked. There is no automatic paid conversion in this implementation. Existing Stripe webhook processing remains intact; a free grant does not cancel an existing paid subscription. Approve eligibility rules that exclude existing paid businesses and verify provider configuration before pilot activation. |
| Grant operations | No audited operator grant/revoke workflow exists. A single mutable row is not an immutable approval/revocation history. Prepare a controlled, auditable provisioning process; do not expose a public self-grant endpoint. |
| Staged SQL | Source assertions cover constraints/RLS/revocations, not executable privilege proof. `GRANT SELECT` alone does not remove privileges inherited from configured default grants. Review service-role DML privileges explicitly, then independently test schema permissions and recovery after separate approval. SQL remains outside automatic migrations and unapplied. |
| Recovery | Verified backup/restore of shared Dev data, Auth, Storage and configuration, plus migration-ledger reconciliation, is still required before any database change. |
| Signup and status copy | Public config advertises the legacy broad pilot flag, not scoped grant status. Signup, approval, expiry and unavailable-state copy must match the actual controlled workflow. |
| CI and release | Existing GitHub test workflows do not target this branch/base; the starting head had only a Vercel feedback check, not a regression check. Local results do not constitute GitHub CI or deployed acceptance. A separately authorised exact-SHA Preview and acceptance are still needed. |
