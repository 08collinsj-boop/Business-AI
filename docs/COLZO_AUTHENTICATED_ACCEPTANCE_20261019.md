## Fix and additive Dev migration

`leads` had no `updated_at` column. Migration `20261019162954_colzo_lead_write_versions.sql`, generated by the Supabase CLI, adds that column and an invoker trigger which assigns a monotonically advancing timestamp on every update, including legacy writes. It does not change existing customer fields, RLS, policies, grants on the table or immutable legacy handler source. Trigger function execution is revoked from public/anon/authenticated and its search path is empty.

The exact SQL was applied once to **Dev only** using the authorised SQL action, before committing/deploying the version-requiring handler. Read-only verification found eight leads before and after, RLS still enabled, the new column/function and exactly one version trigger. This was a direct SQL application; do not assume CLI migration history was registered. The idempotent migration file is committed for reproducibility. No Production migration is authorised.

Colzo's Preview-only Leads handler now requires the exact loaded `expected_updated_at`, checks it without discarding PostgreSQL microseconds, and includes it with business/id filters in the atomic PATCH. A stale pre-read or zero-row race returns 409 before history/audit/follow-up side effects. Missing database version fails closed. A saved representation must have an advanced valid version before success is reported. Native and Preview legacy-view editors send the viewed version; a conflict retains the user's unsaved draft. Unrelated/non-Preview legacy request contracts remain unchanged.
